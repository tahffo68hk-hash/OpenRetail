# 给本地 Agent 的继续开发任务（基于源码，不从零重写）

工程：OpenRetail V2。请先解压源码并阅读 README 与 `docs/PRODUCTION_GATE.md`，本仓库已完成订单预留、幂等、认证、模拟门禁、微信 Native 签名/回调/查单代码，以及 OSPOS/HA/ESPHome/Frigate/ERPNext 基础桥接。

**先复现 `python -m pytest -q` 与 `node --check web/app.js`，然后连续交付下面的已知高优先级缺口，避免重新造轮子：**

1. 根据实际门店的收银/库存来源（OSPOS vs ERPNext vs OpenRetail）确定唯一权威数据源；如使用既有 POS，开发已确认 API 或可靠定时增量同步，而不是直接对外部数据库双写。
2. 接通真实本地服务：Frigate+MQTT、Home Assistant+只读门磁，增加设备心跳、离线告警与异常处理；先不用任何实体开锁权限。
3. 对接适合顾客手机同机付款的官方渠道（微信 JSAPI/小程序/H5、支付宝），接入实际商户条件后再进行逐笔收费 Pilot；补齐退款、日终对账、平台密钥轮换、监控告警。
4. 为无人门禁接入合规实名/手机号提供商与正式门禁 SDK，但在取得门体、消防/失效策略、设备协议与现场验收证据前保留强制 OFF；不要绕开后端安全门禁。
5. 补充多角色操作员权限、实际手机端 E2E、Docker/HTTPS 真实部署及备份恢复演练。

默认 NO PUSH、无真实付费调用、不开真实营业门、不接触未经授权的顾客信息。可逆本地开发自主推进，采用最少充分测试；对实际支付、现场门禁、电气/消防和生产数据迁移保持明确验收条件。只汇报已实测事实、剩余缺口和 Git 状态。
